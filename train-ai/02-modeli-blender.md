# 02. Как создаются 3D-объекты (Blender, только код)

Все модели строятся **процедурно** — Python-скриптом через `bpy`, без ручного моделирования, без скачанных ассетов и без
ИИ-генерации. Плюсы: воспроизводимо, легко править размеры, полный контроль над количеством полигонов, и модели не выглядят
«сгенерированными».

## Соглашения

* Blender: **Z вверх, зритель смотрит с −Y** (фронт модели обращён к −Y). При экспорте `export_yup=True` → в glTF Y вверх.
* Единицы условные: модель порядка 1 по наибольшей стороне. PowerPoint всё равно нормирует размер по габаритам.
* Центр — примерно в начале координат; в конце функция модели делает `shift_all(dz=-…)`/`rig.shift(...)`, чтобы
  модель стояла по центру.
* Одна модель = одна функция `m_<key>()` в `make_models.py`; словарь `MODELS = {"chest": m_chest, …}`;
  `python3 make_models.py chest harp` собирает выбранные. Каждая модель начинается с `mm.reset()` и `mm._mats.clear()`.
* Модели Кантильона импортируют базовые хелперы Шумпетера:
  `sys.path.insert(0, "../../schumpeter/models"); import make_models as mm`.

## Набор строительных функций

Базовые (`presentations/schumpeter/models/make_models.py`):

| Функция | Что делает | Пример использования |
|---|---|---|
| `box(name, size, loc, mat, bevel=0.01, rot, seg)` | брусок со скруглёнными рёбрами (модификатор Bevel) | стенки сундука, обложки, плинтус |
| `cyl(name, r, h, loc, mat, rot, seg, bevel)` | цилиндр | мачта, свиток, ось |
| `sphere(name, r, loc, mat, seg, rings)` | сфера; потом `.scale = (…)` → эллипсоид | шляпки гвоздей, пипсы кубика, тело птицы |
| `torus(name, R, r, loc, mat, rot, seg, mseg)` | тор | кольца ключа, ручки, круги на воде |
| `lathe(name, prof, mat, seg=72, smooth, loc)` | **тело вращения** из профиля `[(r, z), …]` вокруг Z | монета, подсвечник, чернильница, чаши весов, корпус компаса |
| `tube(name, pts, r, mat, res, smooth_curve)` | трубка вдоль ломаной/NURBS-кривой (curve + bevel → mesh) | ствол пера, цепочки весов, такелаж, коромысло |
| `profile2d(name, loops, depth, bevel, mat)` | выдавливание 2D-контура (с дырками) | шестерня, плоские силуэты |
| `mesh_obj(name, verts, faces)` | меш из списков вершин и граней | корпус корабля, лепестки розы компаса, стрелка |
| `finish(obj, mat, smooth, bevel, seg)` | назначить материал, сглаживание по углу, фаску | вызывается всеми хелперами |
| `coin(name, loc, rot, r, t)` | монета с бортиком и рельефными кольцами (lathe) | луидоры, ставки |
| `book(...)` | закрытая книга с корешком и бинтами | стопки книг |
| `rot_all(rx, ry, rz)` | повернуть всю сцену | наклон компаса к зрителю |

Дополнительные (`presentations/cantillon/models/make_models.py`):

| Функция | Что делает |
|---|---|
| `grid_surface(name, nu, nv, fn, mat)` | параметрическая поверхность `fn(u, v) → (x, y, z)`, u,v ∈ [0,1]: паруса, вымпел, море, страницы, перья, крылья |
| `extrude_profile(name, prof, x0, x1, mat)` | замкнутый профиль (y, z), вытянутый вдоль X: полукруглая крышка сундука, оковки |
| `text_mesh(name, body, size, depth, mat, loc, rot)` | объёмный текст (FONT-curve → mesh): «ESSAI», «1720», буквы N/E/S/W |
| `sail(name, corners, billow)` | четырёхугольный парус с «пузом» по синусу |
| `die(name, size, loc, rot)` | игральная кость: скруглённый куб + пипсы-сферы по схеме граней (единица — красная) |
| `xform(objs, T)` / `shift_all(...)` | применить матрицу к набору объектов / сдвинуть всё |
| `flyer(rig, name, …)` | птица или мотылёк с двумя крыльями на костях (см. 03) |

### Приёмы

* **Тела вращения решают половину задач.** Профиль — список `(радиус, высота)`; точка с `r=0` замыкает дно/верх.
  Подсвечник: `[(0,0),(0.30,0),(0.33,0.015),(0.34,0.045),(0.32,0.05),(0.29,0.025),(0.06,0.02),(0,0.02)]`.
* **Корпус корабля** — «лофт» из сечений: для каждого `t` вдоль длины считаются полуширина `w(t)` и высоты борта/днища,
  сечение — полуэллипс из `NS` точек; грани — квады между соседними сечениями; `bmesh.ops.recalc_face_normals`;
  материал по высоте грани (медь ниже ватерлинии, чёрный пояс, орех).
* **Поверхности по формуле** (`grid_surface`): море = синусы + «юбка» (крайние ряды сетки опущены вниз — получается
  толстая плита воды); страница = плоскость с текстовыми строками-брусками; перо = профиль ширины `sin(πu)^0.6` с
  вырезами-«надломами».
* **Детали = правдоподобие.** Заклёпки на оковках, резьба-трилистник на арфе, гравировка «1720» на свитке, лента с печатью
  на акциях, колки на арфе, буквы на циферблате, бортик на монете. Именно мелочи убирают «игрушечность».
* **Объекты, которые зритель должен «прочитать» на слайде**, делаются крупнее реального масштаба (чайка, ноты, мотылёк
  увеличены в ~1.8 раза после первой проверки — в реальном размере были точками).
* **Полости и содержимое.** Если крышка будет открываться — корпус строится из стенок (а не сплошным бруском), внутри
  подкладка, а содержимое ставится на приподнятое дно, чтобы его было видно поверх передней стенки.

## Материалы (палитра `M(name)`)

Один общий набор материалов (Principled BSDF): `name → (базовый цвет, metallic, roughness, extra)`, где extra —
`coat` (лак), `sheen` (ткань/перо), `alpha` (стекло), `emit`+`es` (свечение), `film`+`trans` (мыльная плёнка).
Основные: `brass, brass_d, gold, ivory, paper, walnut, leather, iron, wine, oxblood, canvas, wax, flame, glow, water,
ink, feather, glass, bubble, satin, concrete, sand, green …`.

Правила, выведенные на практике:

* **Хром/зеркальная сталь получаются почти чёрными** — им нечего отражать на тёмном фоне. Металлы держать
  с `roughness ≥ 0.3` (satin), золото/латунь — тёплые.
* Тёмный текст на золоте не читается — на золоте только светлое (ivory/paper).
* Светящиеся материалы (`emit`) — для пламени, окон, фонаря; они дают «живость» и в PowerPoint тоже светятся.
* Белые «блики»/круги на воде делать матовым светлым материалом (`paper`), а не хромом.
* Текстуры не нужны: всё на цвете материалов → маленькие файлы. Если текстура нужна — ≤1K, JPEG.

## Бюджет и экспорт

* 3–30 тыс. треугольников, 0.2–1.6 МБ на `.glb` — PowerPoint крутит такие модели плавно.
  Сегменты: монеты 56, мелкие сферы 10–16, цилиндры-струны 8.
* Перед экспортом: удалить не-меш объекты, **применить все модификаторы** (bevel), `transform_apply`
  (иначе масштабы/повороты разъедутся) — это делает `mm.export(key)` (статичная модель) или
  `rig.export_rigged(...)` (анимированная).
* glTF-экспорт: `export_format="GLB"`, `export_yup=True`, **без Draco** (PowerPoint не читает сжатые меши),
  без камер/ламп/extras.
* Каждая модель печатает `[model] key: N KB, ~T tris, B bones, Ss loop` — это быстрый контроль бюджета.

## Чтобы «не выглядело как ИИ»

* Никаких сгенерированных картинок на слайдах: фон, световое пятно и тень — `stage.py` (numpy-градиенты, виньетка, зерно),
  модели — код, исторические изображения — только реальные (общественное достояние, с подписью).
* Единая предметная «музейная» тема: каждый экспонат — физический предмет эпохи (сундук, перо, весы, свеча), подписанный
  как «ЭКСПОНАТ 03».
* Сдержанная палитра (латунь / слоновая кость / тёмное дерево / винный), никаких неоновых градиентов.
