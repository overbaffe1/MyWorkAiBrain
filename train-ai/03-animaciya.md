# 03. Анимация внутри модели (а не вращение)

Цель: у каждой модели двигаются **её собственные части** — крышка открывается, струны дрожат, страницы листаются,
стрелка мечется, чайка машет крыльями. И это должно играть **внутри PowerPoint**, без видео.

## Главный факт: PowerPoint играет только скелетную анимацию

PowerPoint 365 умеет проигрывать анимацию, встроенную в `.glb`, **но только skinned-анимацию** (кости армутуры +
веса вершин). Не работают:

* анимация трансформаций узлов (node TRS) — то, что получается, если просто анимировать объекты в Blender;
* morph targets / shape keys.

Поэтому каждая подвижная часть привязывается к **кости** одной армутуры, а анимируются только кости.
Дополнительно:

* **одна армутура и одно действие (action)** — отдельные действия на разных объектах экспортируются как отдельные
  glTF-анимации, а PowerPoint играет одну (`animId="0"`);
* лучше всего работают **вращения** и **масштаб** костей; умеренные смещения тоже работают (подъём свитка, прыжок кости);
* длина цикла 4–6 с, ключ на каждый кадр (24 fps).

## `rig.py` — как это устроено

Файл: `presentations/cantillon/models/rig.py`.

```python
rig = Rig()                                   # всегда есть кость "root" (неподвижная база)

m = rig.mark()                                # запомнить, какие объекты уже есть в сцене
...строим крышку (box, extrude_profile, ...)  # всё созданное после mark()
rig.take(m, "lid", head=(0, D/2, H))          # → привязать к новой кости "lid" с шарниром в head

m = rig.mark(); ...ключ...; rig.take(m, "key", head=keyhole)
rig.bone("pen1", (-0.11, 0, 1.78), parent="pen0")   # кость без своих объектов (для цепочки/весов)
rig.take_fn(m, "pennant", lambda co: {...})   # плавные веса: функция от координаты вершины

rig.shift(dz=-0.38)                           # сдвиг всей модели — двигает и меши, и шарниры костей
rig.rotate(rx=62)                             # наклон всей модели (компас) — оси анимации поворачиваются тоже

def anim(t):                                  # t ∈ [0, 1) — нормированное время цикла
    return {"lid": {"rot": [((1, 0, 0), -98 * ease(t, 0.14, 0.34))]},
            "key": {"rot": [((0, 1, 0), 90 * ease(t, 0.03, 0.12))]}}

return rig, anim, 5.0                          # функция модели возвращает (rig, anim, секунды)
# main: res = MODELS[key](); export_rigged(key, *res) если вернула кортеж, иначе mm.export(key)
```

### Формат позы, которую возвращает `anim(t)`

`{имя_кости: {"rot": [(ось, градусы), …], "loc": (dx, dy, dz), "scale": s | (sx, sy, sz)}}`

* Оси и смещения задаются **в системе координат модели** (Z вверх, зритель с −Y) *до* `rig.rotate()`.
* Несколько вращений применяются по порядку (первое — первым).
* Вращение — вокруг **шарнира** кости (`head`). Для дочерних костей поза задаётся относительно родителя
  (пример: чаша весов компенсирует наклон коромысла `-beam + lag` и поэтому висит отвесно).
* `scale` — масштаб вокруг шарнира; `0.001` = «спрятать» (лопнувший пузырь, ещё не появившиеся круги на воде).

### Что делает `export_rigged(key, rig, anim, seconds)`

1. Удаляет не-меш объекты, применяет модификаторы и трансформации.
2. **Объединяет объекты по костям** (`bpy.ops.object.join` через `temp_override`) — меньше узлов, быстрее в PowerPoint.
3. Создаёт армутуру `rig`: каждая кость от `head` вверх по +Z на 0.08 — у всех костей **одинаковая ориентация покоя**
   (это упрощает перевод осей).
4. Веса: обычная часть — одна группа вершин с весом 1; для `take_fn` — веса из функции, нормированные; модификатор
   Armature, меши — дети армутуры.
5. Запекание: для каждого кадра `f = 0…N` (`N = seconds·24`) берётся `t = f/N`, поза переводится из мировых осей в
   локальные оси кости: `q_local = Rrest⁻¹ · q_world · Rrest`, `loc_local = Rrest⁻¹ · (R_model · d)`,
   масштаб `(sx, sy, sz)` → `(sx, sz, sy)` (локальная Y кости = мировая Z); ключи `rotation_quaternion / location / scale`.
6. Экспорт glTF с `export_animations=True, export_skins=True, export_force_sampling=True, export_frame_range=True,
   export_animation_mode="ACTIVE_ACTIONS", export_def_bones=False, export_rest_position_armature=True, export_yup=True`,
   без Draco. Параметры фильтруются по реально существующим в этой версии Blender
   (`bpy.ops.export_scene.gltf.get_rna_type().properties.keys()`), чтобы скрипт не падал на других версиях.

## Правила хорошей анимации

* **Бесшовный цикл:** поза при `t = 0` и `t = 1` совпадает. Используются периодические функции с целым числом
  периодов на цикл (`sin(2π·k·t)`), сценарии «открыть → подержать → закрыть», частицы со `scale = sin(π·u)`
  (на концах жизни = 0, поэтому прыжок назад не виден).
* **Кадр 0 = постер.** Растр-заглушка в pptx и постер PowerPoint — это поза `t = 0`. Если она скучная (пустая миска),
  сдвинуть фазу: `return rig, (lambda t: anim((t + 0.42) % 1.0)), 4.0`.
* **Не выходить далеко за габариты покоя.** PowerPoint кадрирует модель по габаритам в позе покоя; камера стоит на
  расстоянии описанной сферы, так что есть запас ~20–40 %, но не больше. Пузырь раздувается максимум до ×1.10, дым
  поднимается невысоко, открытая крышка помещается в сферу.
* **Сценарий, а не дёрганье:** у каждого экспоната маленькая история с паузами — ключ → крышка → свиток → монеты → закрыть.
* **Вторичное движение** оживляет: запаздывание чаш весов за коромыслом, изгиб страницы при перелистывании,
  затухающая вибрация, «планирование» птицы с остановкой крыльев.

### Хелперы времени (в `rig.py`)

| Функция | Значение |
|---|---|
| `ease(t, a, b)` | 0 до `a`, плавно 0→1 на `[a, b]`, 1 после `b` (smoothstep) |
| `pulse(t, a, b, c, d)` | 0→1 на `[a,b]`, держит, 1→0 на `[c,d]` |
| `back_out(x, s)` | с перелётом (крышка «откидывается» с отскоком) |
| `hop(x)` | парабола 0→1→0 (прыжок) |
| `wave(t, k, ph)` | `sin(2π(k·t + ph))` |
| `clamp01`, `smooth` | служебные |
| `puff_pose(t, k, n, rise, drift)` | частица (дым, ноты): поднимается, растёт, исчезает; `n` штук со сдвигом фаз |
| `flyer(...)` + `flyer_pose(...)` | птица/мотылёк: кость орбиты + две кости крыльев |

## Рецепты (всё взято из `cantillon/models/make_models.py`)

**Крышка на петлях (сундук).** Кость в линии петель `(0, D/2, H)`, вращение вокруг X. Отрицательный угол поднимает
передний край. `lid = -98 * back_out((t-0.14)/0.20) * (1 - ease(t, 0.78, 0.91))`. Ключ — кость в замочной скважине,
поворот 90° вокруг Y до открытия и обратно после закрытия. Свиток: `loc z` + небольшой наклон, пока крышка открыта.
Монеты: `hop` по высоте + полный оборот 360° (на конце снова «орёл»).

**Струны (арфа).** Кость на верхнем конце струны; цилиндр струны поделён на 15 колец; веса
`w = sin(π·u)^1.3` (u — доля длины от верха) — концы закреплены, середина гнётся. Поворот кости вокруг X —
затухающая синусоида: `ang += 11·exp(-(t-t0)/0.10)·sin(2π·22·(t-t0))`; `t0` у струн сдвинуты — глиссандо вверх и вниз.

**Волны (море под кораблём).** 8 костей вдоль X; вершины поверхности воды — гауссовы веса по X
(`exp(-((x-xi)/0.26)^2)`); каждая кость двигается по Z: `0.036·sin(2π(t - xi/λ))` → бегущая волна.
Нижние вершины «юбки» — на root. Корпус: тангаж `cos`, крен `sin` со сдвигом фазы, лёгкая вертикальная качка.

**Цепочка (вымпел).** 3 кости-цепочки (`pen0 → pen1 → pen2`), треугольные веса вдоль длины, вращение вокруг Z с
нарастающей амплитудой и запаздыванием фазы — флаг «полощется».

**Паруса.** Кость на рее; вращение вокруг оси реи `±4° + 1.6°` гармоникой — паруса «дышат».

**Страницы (книга).** На каждую страницу 2 кости: `a` — у корешка (переворот 0 → −178°), `b` — на середине (изгиб).
Веса по X: `wb = smooth((u-0.3)/0.6)`. Изгиб `-38·sin(π·p)` во время переворота. Строки текста — тонкие бруски с обеих
сторон страницы (после переворота видна обратная сторона). Все страницы вместе возвращаются в конце цикла.

**Пузырь.** Кость в центре сферы: масштаб растёт до 1.10 с «желейной» деформацией `sx·(1+w), sz·(1-w)`,
затем за 3 % цикла → 0.02 (хлоп), пауза, `back_out` обратно до 1. Свиток внутри падает на акции; верхние листы
акций подлетают с вращением.

**Весы.** Коромысло: `7·sin(2πt) + 1.6·sin(6πt + …)`; чаши — дочерние кости: `−beam + 2.2·sin(2πt − 0.12)`
(висят отвесно, но с запаздыванием); кость-кубик парит над чашей и вращается.

**Кости (кубики).** 4 прыжка за цикл, каждый — `hop` по высоте и +90° вокруг горизонтальной оси кубика (за цикл 360°),
у второго кубика фаза сдвинута на полпрыжка. Монета-волчок: кость в точке касания, вращение вокруг Z 4 оборота
+ покачивание вокруг X.

**Монета в воду.** Падение с ускорением `z = -0.40·q²` и вращением, после удара — уход под воду и масштаб → 0;
4 кольца-тора: масштаб по XY 0.4 → 5.7, по Z → 0 (кольцо «растекается» и тает), старт со сдвигом; корона брызг —
масштаб вверх и обратно.

**Компас.** Модель наклонена `rig.rotate(rx=62)`, ось стрелки поворачивается автоматически. Толчок корпуса
`5·sin(2π·10t)·exp(-t/0.035)`, стрелка — затухающие колебания `75·(1-e^(-t/0.015))·e^(-t/0.20)·cos(2π·3.2t)`.

**Пламя.** Масштаб из суммы синусов с целыми частотами (3, 7, 13 и 5, 11, 17 периодов за цикл) — выглядит как случайное
мерцание, но цикл бесшовный; лёгкое покачивание; внутреннее ядро пламени — дочерняя кость со своим ритмом.
Дым — `puff_pose`, мотылёк — `flyer` с орбитой вокруг огня.

**Птица / мотылёк (`flyer`).** Кость орбиты в центре круга (вращение вокруг Z на 360°·turns), тело стоит на радиусе
и смотрит по касательной (+Y); кости крыльев у плеч — дети орбиты: левое `+A·sin(2π·f·t)`, правое `−A·sin(...)`
вокруг оси полёта; `glide=(a,b,c,d)` останавливает взмахи на отрезке цикла (птица планирует).

## Как проверять анимацию без PowerPoint

`models/anim_preview.py` **заново импортирует экспортированный `.glb`** (то есть ровно то, что получит PowerPoint),
ставит кадры через `scene.frame_set` и рендерит раскадровку + GIF в `models/_anim/`:

```bash
LD_LIBRARY_PATH=/tmp/bstub FRAMES=8 PX=380 ROT="16,-28,0" python3 models/anim_preview.py chest harp
KEEP=1 FRAMES=16 PX=260 python3 models/anim_preview.py ship harp ...   # оставить кадры
python3 models/anim_sheet.py ../../exports/x-animations-preview.gif ship harp ...   # сетка-GIF для пользователя
```

Смотреть раскадровку обязательно: на ней сразу видно мелкие (нечитаемые) детали, неправильный знак угла,
выход за кадр, тёмные материалы.
